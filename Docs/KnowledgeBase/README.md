# 《明路》策划知识库

这个目录是给新加入项目的策划用的入口。目标不是把所有细节一次性塞给新人，而是让每个岗位知道自己该从哪里开始、改哪些文件、用什么工具验证，以及哪些规则不能破坏。

## 新人第一天

1. 先读本页，理解项目目录和协作方式。
2. 再读 [岗位协作手册](岗位协作手册.md)，找到自己的岗位职责和交付物。
3. 准备改数值或文案前，读 [导表与配置流程](导表与配置流程.md)。
4. 准备提交给程序或测试前，读 [验收与提交流程](验收与提交流程.md)。
5. 不懂术语时查 [术语表](术语表.md)。

## 项目当前形态

《明路》是 Unity 单机原型，核心体验由三部分循环组成：

| 模块 | 玩家做什么 | 策划关注点 |
| --- | --- | --- |
| 学院养成 | 上课、休息、社交、读报、推进剧情 | 属性成长、任务闸门、好感和日常事件 |
| 战棋战斗 | 移动单位、攻击、守点、达成关卡目标 | 兵种克制、地形、AI、胜负目标、剧情触发 |
| 战略地图 | 选择军团、行军、进攻、回合推进 | 省份、军团、补给、情报、战功奖励 |

剧情只负责串联和解释玩法结果。不要用剧情替玩家推进核心玩法，主线、支线和任务都应该被养成、社交、情报、战棋结果触发。

## 常用目录

| 路径 | 用途 |
| --- | --- |
| `Assets/Scripts/MingLuGame.cs` | 当前主要游戏逻辑和运行时 UI。策划一般不直接改，除非和程序一起确认。 |
| `Assets/Resources/Data/MingLuGameConfig.json` | 运行时读取的系统配置、数值、UI 文案。由导表生成。 |
| `Assets/Resources/MingLuStoryData.json` | 运行时读取的剧情事件、对白、选项。由导表生成。 |
| `Assets/Resources/Art` | 角色立绘、场景、战棋单位、地形和 UI 素材。 |
| `DataTables/MingLu_GameTables.xlsx` | 总览用 Excel 工作簿，方便策划检查整套配置。 |
| `DataTables/csv` | 真正参与回写的 CSV 源文件。策划改表优先改这里。 |
| `Docs` | 设计文档、UI 方案、战斗 AI 和本知识库。 |
| `Tools` | 导表、检查、打包、美术生成等脚本。 |

## 常用入口

| 入口 | 适用场景 |
| --- | --- |
| `导出配置表.bat` | 从工程当前配置导出 CSV 和总表。 |
| `回写配置表.bat` | 把 `DataTables/csv` 回写到 Unity 运行时 JSON。 |
| `检查配置表.bat` | 检查 CSV/JSON 是否有明显缺字段、坏引用或格式错误。 |
| `一键打包安装包.bat` | 生成 Windows 测试包和安装包。 |
| 游戏内 `战棋工坊` | 快速设计和测试战棋地图、地形、单位、目标和剧情触发。 |

## 项目规则

| 规则 | 原因 |
| --- | --- |
| 文案和数值优先走导表，不直接写死到代码。 | 后续才能批量平衡、校对和回滚。 |
| 剧情选项文本必须完整显示，不使用省略号代替关键信息。 | 玩家要能理解选择含义。 |
| 剧情选项的数值影响默认不展示。 | 让剧情服务代入，数值暗中生效。 |
| UI 信息能收纳就收纳，不把所有表格字段平铺在主界面。 | 当前界面目标是清楚，不是做数据后台。 |
| 战棋单位没有移动和攻击时保持静止待机。 | 避免战场视觉噪音。 |
| 新功能要先有可测试路径。 | 原型阶段最怕功能存在但无法验证。 |
