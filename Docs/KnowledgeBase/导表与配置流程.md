# 导表与配置流程

项目中的数值、系统文案、剧情文案和大量内容都要可配置。策划改动优先走 `DataTables/csv`，再回写到运行时 JSON。

## 一句话流程

```text
导出配置表 -> 修改 CSV -> 检查配置表 -> 回写配置表 -> 进 Unity Play 验证
```

## 文件关系

| 文件或目录 | 作用 |
| --- | --- |
| `DataTables/csv` | 策划主要编辑区。 |
| `DataTables/MingLu_GameTables.xlsx` | 总览工作簿，适合查表、对照和给非程序同事看。 |
| `Assets/Resources/Data/MingLuGameConfig.json` | 游戏运行时读取的系统配置。 |
| `Assets/Resources/MingLuStoryData.json` | 游戏运行时读取的剧情配置。 |
| `Tools/export_game_tables.js` | 从运行时配置导出 CSV 和总表。 |
| `Tools/import_game_tables.js` | 从 CSV 回写运行时配置。 |
| `Tools/validate_game_tables.js` | 检查表格引用和基础格式。 |

## 常用批处理

| 脚本 | 什么时候用 |
| --- | --- |
| `导出配置表.bat` | 开始改表前，先把当前工程配置导出到 `DataTables/csv`。 |
| `检查配置表.bat` | 改完 CSV 后先检查，避免坏引用进工程。 |
| `回写配置表.bat` | 检查通过后，把 CSV 写回 `Assets/Resources`。 |
| `一键打包安装包.bat` | 需要给别人玩测试包时使用。 |

## 推荐改表顺序

1. 打开项目根目录。
2. 双击 `导出配置表.bat`。
3. 修改 `DataTables/csv` 中对应 CSV。
4. 双击 `检查配置表.bat`。
5. 检查通过后双击 `回写配置表.bat`。
6. 打开 Unity，等待资源重新导入。
7. 进入对应界面验证。

## 字段填写规则

| 类型 | 写法 |
| --- | --- |
| ID | 用英文、小写、下划线，稳定后不要随便改。 |
| 多值字段 | 用英文分号 `;` 分隔，例如 `xinjing;hegu`。 |
| 空值 | 留空，不写 `无`、`none` 或 `-`，除非字段说明要求。 |
| 数字 | 直接写整数，不带中文单位。 |
| 百分比 | 看字段名，若字段是 `Percent` 通常写 `8` 表示 8%。 |
| 资源路径 | 写 `Resources` 下的相对路径，不带扩展名。 |

## 剧情触发字段

`story_events.csv` 的触发字段是剧情和玩法衔接的关键：

| 字段 | 用法 |
| --- | --- |
| `unlockKind` | 条件类型，例如 `quest`、`story`、`battleWins`、`anyCourseLevel`、`intelligence`。 |
| `unlockTarget` | 目标 ID，例如任务 ID、剧情 ID、角色 ID。没有目标可留空。 |
| `unlockValue` | 阈值，例如胜利次数、课程等级、情报值。 |
| `unlockHint` | 条件不足时给玩家看的提示。 |

## 改表检查清单

提交给程序前，至少确认：

| 检查项 | 通过标准 |
| --- | --- |
| ID 唯一 | 新增行没有和旧 ID 重复。 |
| 引用存在 | 任务引用的剧情、剧情引用的角色、单位引用的资源都存在。 |
| 文本完整 | 按钮、选项和弹窗没有用省略号藏信息。 |
| 数值可测 | 新数值有至少一个可进入游戏验证的路径。 |
| 回写成功 | `检查配置表.bat` 和 `回写配置表.bat` 没报错。 |

## 什么时候不要改表

以下情况先找程序或主策确认：

| 情况 | 原因 |
| --- | --- |
| 需要新字段 | 程序必须先支持读取和使用该字段。 |
| 需要新界面入口 | 只是加表不会自动出现按钮。 |
| 需要新战斗胜负规则 | 战棋引擎需要接判定。 |
| 需要新资源加载方式 | 美术资源命名和路径要同步改。 |
