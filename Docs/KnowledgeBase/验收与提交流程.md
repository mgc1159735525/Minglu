# 验收与提交流程

策划交付的目标是让程序、测试和其他策划能直接接手。不要只说“我改完了”，要说明改了什么、在哪里看、怎么验证。

## 需求交付模板

```text
需求名称：
负责人：
相关模块：
玩家入口：
改动文件：
改动摘要：
验证步骤：
预期结果：
风险点：
暂不处理：
```

## 内容改动验收

| 内容类型 | 必测路径 |
| --- | --- |
| 创角 | 新游戏 -> 创建角色 -> 不填名字 -> 默认名是否正确 -> 完成入学。 |
| 学院养成 | 学院主界面 -> 选择课程或周末活动 -> 看属性等级、体力、心情、日志。 |
| 剧情 | 剧情目录或自动触发 -> 条件不足提示 -> 条件满足推进 -> 选项后返回。 |
| 任务 | 任务日志 -> 接取或显示目标 -> 完成条件 -> 奖励发放 -> 后续任务。 |
| 社交 | 学院邀约 -> 好感变化 -> 好感段位或支线解锁。 |
| 战棋 | 战略地图或战棋工坊 -> 选单位 -> 移动 -> 攻击 -> 胜负结算。 |
| 战棋关卡 | 战棋工坊 -> 改地形/单位/目标/触发器 -> 保存 -> 开始测试。 |
| 战略地图 | 选择军团 -> 行军或进攻 -> 回合结束 -> 敌方 AI 行动。 |
| 情报 | 设置或情报入口 -> 执行动作 -> 成本、成功率、奖励和风险反馈。 |

## UI 验收标准

| 项目 | 标准 |
| --- | --- |
| 文本 | 不超框，不遮挡按钮，不使用省略号替代核心选择。 |
| 按钮 | 主操作明显，次操作收纳，不能全横排挤在一起。 |
| 弹窗 | 右上角有关闭按钮，返回路径明确。 |
| 信息层级 | 主界面只放决策必须信息，详情放按钮和弹窗。 |
| 玩家反馈 | 每次重要点击都有状态、日志、弹窗或数值变化。 |

## 数值验收标准

| 项目 | 标准 |
| --- | --- |
| 初始值 | 新游戏后和表中一致。 |
| 成长 | 等级、经验进度条和奖励符合表格设计。 |
| 战斗 | 伤害、移动、射程、地形和克制能在战斗中体现。 |
| 奖励 | 战功、国库、好感、情报、称号等发放准确。 |
| 边界 | 低体力、补给不足、敌我全灭、条件不足都有反馈。 |

## 战棋关卡验收标准

| 项目 | 标准 |
| --- | --- |
| 地图 | 尺寸正确，格子可点，扩大后仍居中显示。 |
| 地形 | 地形颜色、名称、防御和移动消耗一致。 |
| 单位 | 蓝方和红方至少各有一个单位，资源能显示。 |
| 目标 | 占据据点、抵达据点、击溃敌军都能正确结算。 |
| 触发器 | 抵达区域和击败指定敌人能弹出剧情。 |
| AI | 敌方能移动、攻击、待命或防守，不在回合中卡死。 |

## Bug 提交模板

```text
标题：
严重程度：阻断 / 高 / 中 / 低
发生位置：
复现步骤：
实际结果：
期望结果：
是否必现：
截图：
最近改动：
备注：
```

严重程度参考：

| 等级 | 定义 |
| --- | --- |
| 阻断 | 无法进入游戏、无法继续流程、存档损坏、战斗卡死。 |
| 高 | 核心功能错误，例如任务无法完成、战斗结算错误。 |
| 中 | 体验明显问题，例如 UI 超框、提示错误、数值异常。 |
| 低 | 文案错字、轻微排版、非关键提示不准。 |

## 提交给程序前

策划提交内容前，请确认：

| 检查项 | 说明 |
| --- | --- |
| 有入口 | 程序知道从哪里打开或触发。 |
| 有数据 | 新内容已经落到 CSV 或文档中。 |
| 有例子 | 至少给一个可复制的测试样例。 |
| 有边界 | 说明失败、条件不足、空值时怎么表现。 |
| 有截图或录屏 | UI、关卡、bug 类问题尽量附图。 |

