# 岗位协作手册

本手册按策划岗位说明如何参与《明路》开发。一个人可以兼任多个岗位，但交付物要按岗位拆清楚，方便程序、美术和测试接手。

## 主策和执行策划

| 项目 | 内容 |
| --- | --- |
| 主要职责 | 定义版本目标，拆功能范围，判断哪些内容先做、哪些内容延期。 |
| 常改内容 | `Docs/MingLu_FeaturePlan.md`、阶段需求清单、验收标准。 |
| 交付物 | 功能目标、玩家流程、最小可测版本、延期项说明。 |
| 验收方式 | 进入游戏后能完成一条完整体验链，而不是只看到孤立按钮。 |

写需求时必须包含：

```text
功能名称：
玩家为什么需要它：
入口在哪里：
玩家操作流程：
涉及的表：
成功/失败反馈：
最小验收标准：
不做范围：
```

## 系统策划

| 项目 | 内容 |
| --- | --- |
| 主要职责 | 设计养成、战斗、战略、任务、称号、成就、情报等系统规则。 |
| 常改表 | `academy_core.csv`、`battle_core.csv`、`supply_rules.csv`、`quests.csv`、`achievements.csv`、`titles.csv`、`intelligence_actions.csv`。 |
| 交付物 | 规则说明、字段说明、默认参数、边界情况。 |
| 验收方式 | 玩家能看懂目标，系统能稳定给反馈，失败时知道差什么条件。 |

系统策划不要只给概念，要给可落表字段。例如“情报影响战前准备”要拆成：

| 字段 | 示例 |
| --- | --- |
| 行动名称 | 战前侦察 |
| 消耗 | 情报值 8 |
| 成功率 | 70 |
| 奖励 | 敌军兵力 -12，情报网 +1 |
| 风险 | 失败时敌军警戒 +1 |

## 数值策划

| 项目 | 内容 |
| --- | --- |
| 主要职责 | 平衡成长速度、兵种强度、伤害公式、补给、奖励和敌我强度曲线。 |
| 常改表 | `battle_roles.csv`、`battle_role_damage_rules.csv`、`health_factors.csv`、`battle_core.csv`、`academy_levels.csv`、`exam_rewards.csv`、`ranks.csv`。 |
| 交付物 | 目标曲线、关键数值表、改动理由、测试样例。 |
| 验收方式 | 低级、中级、高级样例都能跑通，没有一眼无敌或无用的选择。 |

数值改动建议附 3 个样例：

| 样例 | 要看什么 |
| --- | --- |
| 新手样例 | 第一场战棋是否能理解和获胜。 |
| 标准样例 | 同等级敌我是否接近期望胜率。 |
| 压力样例 | 补给不足、体力低、克制不利时是否明显变难但不崩。 |

## 剧情策划

| 项目 | 内容 |
| --- | --- |
| 主要职责 | 写主线、支线、日常碎片、战场剧情和选项文案。 |
| 常改表 | `story_events.csv`、`story_lines.csv`、`story_choices.csv`、`story_characters.csv`、`narrative_fragments.csv`、`quests.csv`。 |
| 交付物 | 事件 ID、触发条件、对白、选项、后续跳转、暗中效果。 |
| 验收方式 | 条件不足时能看到提示，条件满足后能推进，不出现死链。 |

剧情写作原则：

| 原则 | 说明 |
| --- | --- |
| 先玩法后剧情 | 剧情解释玩家为什么训练、社交、侦察、出战。 |
| 选项完整 | 选项不能用省略号藏关键信息。 |
| 影响暗中生效 | 好感、立场、属性可以变化，但不要直接把数值堆给玩家。 |
| 触发有条件 | 主线和重点支线必须有 `unlockKind / unlockTarget / unlockValue`。 |

## 任务策划

| 项目 | 内容 |
| --- | --- |
| 主要职责 | 把主线目标、角色请求、派系命令和日常目标转成可完成任务。 |
| 常改表 | `quests.csv`、`story_events.csv`、`narrative_fragments.csv`。 |
| 交付物 | 任务链、解锁条件、完成条件、奖励、失败或卡住提示。 |
| 验收方式 | 任务能引导玩家回到核心玩法，而不是只让玩家点剧情。 |

任务应该写成“行为目标”，不要写成“看完剧情”。例如：

| 不推荐 | 推荐 |
| --- | --- |
| 阅读训练搭档剧情 | 任意同窗好感达到 30 |
| 等待兵棋资格开启 | 任意课程达到 Lv.2 |
| 进入战争章节 | 赢得 1 场战棋 |

## 战斗和关卡策划

| 项目 | 内容 |
| --- | --- |
| 主要职责 | 设计兵种、地形、地图、AI 风格、胜负目标和战场剧情触发。 |
| 常改表 | `battle_roles.csv`、`common_units.csv`、`terrain_rules.csv`、`battle_terrain_tiles.csv`、`battle_unit_spawns.csv`、`ai_profiles.csv`。 |
| 工具入口 | 游戏内 `战棋工坊`。 |
| 交付物 | 地图尺寸、地形分布、双方单位、目标类型、触发剧情、推荐难度。 |
| 验收方式 | 至少亲自测试 2 次：一次正常打法，一次故意走偏。 |

战棋工坊当前支持：

| 功能 | 用法 |
| --- | --- |
| 扩大地图 | 用 `行 +/-`、`列 +/-` 调整地图尺寸。 |
| 自定义地形 | 选择地形刷子，切换地形后点击格子。 |
| 布置单位 | 选择兵种，再用蓝方或红方刷子落子。 |
| 设立目标 | 切换目标类型，占据据点、抵达据点、击溃敌军。 |
| 剧情触发 | 用抵达剧情或击败剧情刷子点击关键格。 |
| 区域触发 | 切换画笔尺寸后放置触发器，角色进入区域或目标在区域内被击败即可触发。 |
| 触发动作 | 触发剧情时可刷援军、调整士气、直接判定胜利或失败。 |
| 文件共享 | 在文件页导出 JSON，提交给程序或其他策划复用。 |
| 测试 | 点击开始测试，结果不会写入正式存档。 |

## UI/UX 策划

| 项目 | 内容 |
| --- | --- |
| 主要职责 | 梳理界面层级、信息收纳、按钮布局、弹窗规则和文字容量。 |
| 常改内容 | UI 文案在 `ui_texts.csv`，界面规则在 `Docs`。 |
| 交付物 | 页面目的、主操作、次操作、弹窗内容、显示和隐藏的信息。 |
| 验收方式 | 玩家第一眼知道该点哪里，文本不超框，按钮不堆成一排。 |

UI 设计约束：

| 约束 | 说明 |
| --- | --- |
| 主界面只放高频信息 | 详情放进按钮和弹窗。 |
| 所有弹窗右上角要有关闭按钮 | 避免玩家不知道如何退出。 |
| 选项按钮自适应文本 | 不用省略号截断选项核心内容。 |
| 不展示表格数据量 | 玩家只看内容，不看开发统计。 |

## 角色和社交策划

| 项目 | 内容 |
| --- | --- |
| 主要职责 | 设计同窗、派系关系、好感事件、性格和特质。 |
| 常改表 | `relationships.csv`、`relationship_levels.csv`、`character_origins.csv`、`creation_memories.csv`、`creation_talents.csv`、`traits.csv`。 |
| 交付物 | 角色定位、初始好感、解锁节点、性格关键词、玩法作用。 |
| 验收方式 | 社交选择能影响任务、剧情或战斗准备。 |

角色不是只写设定。每个主要角色至少要有：

| 内容 | 要求 |
| --- | --- |
| 派系或圈层 | 决定他在政治和任务里的位置。 |
| 好感用途 | 达到某一段位后给线索、任务、战棋建议或支援。 |
| 事件树 | 至少有认识、熟悉、信任三个阶段。 |
| 玩法连接 | 和课程、情报、战棋或战略至少连接一处。 |

## 美术配置策划

| 项目 | 内容 |
| --- | --- |
| 主要职责 | 维护立绘、场景、战棋单位、UI 按钮和资源命名关系。 |
| 常看目录 | `Assets/Resources/Art/Portraits`、`Scenes`、`BattleUnits`、`Terrain`、`UI`、`Manifests`。 |
| 交付物 | 资源清单、命名、尺寸、用途、替换说明。 |
| 验收方式 | Unity 中实际能显示，不只是在文件夹里存在。 |

资源必须能被 `Resources.Load` 路径找到。不要只把图片放进工程，还要确认配置表或代码里引用的路径正确。

## QA 和体验策划

| 项目 | 内容 |
| --- | --- |
| 主要职责 | 验证流程、记录问题、复现 bug、判断体验是否达标。 |
| 常用入口 | Unity Play、战棋工坊、创角、学院、剧情目录、战略地图、打包工具。 |
| 交付物 | 复现步骤、期望结果、实际结果、截图、严重程度、关联模块。 |
| 验收方式 | 问题描述能让程序不追问就复现。 |

Bug 记录模板：

```text
标题：
版本或日期：
入口：
复现步骤：
实际结果：
期望结果：
是否必现：
截图或日志：
影响范围：
```
