# 《明路》新人安装与拉取项目教程

这份教程给第一次加入项目的同学使用。按步骤做完后，本机就能打开 Unity 工程、运行游戏，并且能把自己的改动提交到 GitHub。

## 你需要准备

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10 / Windows 11 |
| 磁盘空间 | 至少预留 15 GB，推荐把项目放在 D 盘 |
| GitHub 仓库 | `https://github.com/mgc1159735525/Minglu.git` |
| Unity 版本 | `2022.3.62f3` |
| 必装工具 | Git for Windows、Git LFS、Unity Hub、Unity Editor 2022.3.62f3 |
| 推荐工具 | VS Code 或 Visual Studio，用来看脚本和文档 |

不要直接点 GitHub 网页上的 `Download ZIP`。项目用了 Git LFS 管资源，下载 ZIP 容易拿不到真正的图片和表格资源。

## 第一步：注册或登录 GitHub

如果只是下载公共仓库，可以不登录也能 clone。  
如果要提交改动，必须有 GitHub 账号，并让仓库负责人把你加为 collaborator。

仓库负责人添加协作者的位置：

```text
GitHub 仓库页面 -> Settings -> Collaborators -> Add people
```

## 第二步：安装 Git 和 Git LFS

1. 打开 Git 官网：`https://git-scm.com`
2. 下载并安装 `Git for Windows`。
3. 安装时大部分选项保持默认即可。
4. 安装完成后打开 `cmd`，输入：

```bat
git --version
git lfs version
```

能看到版本号就说明安装成功。

如果 `git lfs version` 报错，单独安装 Git LFS：

```text
https://git-lfs.com
```

安装后再执行：

```bat
git lfs install
```

## 第三步：配置 Git 用户信息

第一次使用 Git 的同学需要配置姓名和邮箱：

```bat
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
git config --global core.quotepath false
```

`core.quotepath false` 用来让中文文件名在命令行里正常显示。

## 第四步：克隆项目

推荐把项目放在 `D:\paotuan`。

打开 `cmd`，执行：

```bat
D:
mkdir D:\paotuan
cd /d D:\paotuan
git clone https://github.com/mgc1159735525/Minglu.git MingLuUnity
cd MingLuUnity
git lfs pull
```

完成后，本地项目路径应该是：

```text
D:\paotuan\MingLuUnity
```

检查是否成功：

```bat
git status
git lfs ls-files
```

`git status` 正常显示 `On branch main`，`git lfs ls-files` 能列出 png、xlsx、docx 等资源，就说明项目和资源都拉下来了。

## 第五步：安装 Unity Hub 和 Unity Editor

1. 安装 Unity Hub。
2. 在 Unity Hub 里安装 Unity Editor `2022.3.62f3`。
3. 安装模块至少勾选：

```text
Windows Build Support (IL2CPP)
Microsoft Visual Studio Community 或 Visual Studio Editor 支持项
```

如果 Unity Hub 找不到 `2022.3.62f3`，让负责人发 Unity Archive 链接，或者安装同一个 `2022.3.62f3` 长期支持版本。

## 第六步：打开 Unity 工程

1. 打开 Unity Hub。
2. 点击 `Add / 添加`。
3. 选择目录：

```text
D:\paotuan\MingLuUnity
```

4. 用 Unity `2022.3.62f3` 打开。
5. 第一次打开会导入资源，可能需要几分钟，等它完成。

不要提交 Unity 自动生成的这些目录：

```text
Library/
Temp/
Logs/
Builds/
UserSettings/
```

项目已经有 `.gitignore`，正常情况下 Git 会自动忽略它们。

## 第七步：运行游戏验证

Unity 打开后：

1. 打开场景：

```text
Assets/Scenes/Main.unity
```

2. 点击 Unity 顶部 `Play`。
3. 能进入《明路》标题界面就说明工程可运行。

建议新人第一次验证这些入口：

| 入口 | 验证点 |
| --- | --- |
| 新游戏 | 创角界面能打开，不填名字默认是夏邑。 |
| 学院 | 课程按钮、角色信息、事件入口能显示。 |
| 剧情目录 | 剧情能打开，条件不足有提示。 |
| 战略地图 | 能看到省份和军团。 |
| 战棋工坊 | 能放单位、改地形、开始测试。 |

## 第八步：日常更新项目

每天开始工作前，先拉最新版本：

```bat
cd /d D:\paotuan\MingLuUnity
git switch main
git pull
git lfs pull
```

如果项目很久没开，Unity 重新导入资源是正常的。

## 第九步：建立自己的工作分支

不要所有人都直接在 `main` 上改。新人先从 `main` 建自己的分支。

常用分支命名：

| 岗位 | 分支示例 |
| --- | --- |
| 策划表格 | `design/你的名字-tables` |
| 剧情文案 | `story/你的名字-events` |
| 美术资源 | `assets/你的名字-art` |
| 战棋关卡 | `battle/你的名字-levels` |
| UI 调整 | `ui/你的名字-layout` |

创建分支：

```bat
git switch main
git pull
git switch -c design/your-name-tables
```

第一次推送这个分支：

```bat
git push -u origin design/your-name-tables
```

## 第十步：提交自己的改动

改完后先看状态：

```bat
git status
```

提交：

```bat
git add .
git commit -m "说明这次改了什么"
git push
```

提交说明要写人话，例如：

```text
补充第一章剧情触发条件
调整步兵和骑兵基础数值
新增战棋工坊测试地图
替换主角立绘资源
```

不要写：

```text
update
111
随便改改
```

## 策划改表流程

策划改数值和文案时，优先改：

```text
DataTables/csv
```

推荐流程：

```text
双击 导出配置表.bat
修改 DataTables/csv 里的 CSV
双击 检查配置表.bat
双击 回写配置表.bat
进 Unity Play 验证
git add .
git commit
git push
```

常见表：

| 表 | 用途 |
| --- | --- |
| `ui_texts.csv` | UI 文案、按钮、提示、日志。 |
| `player_defaults.csv` | 玩家初始值和默认名字。 |
| `story_events.csv` | 剧情事件和触发条件。 |
| `story_lines.csv` | 剧情对白。 |
| `story_choices.csv` | 剧情选项和效果。 |
| `quests.csv` | 任务解锁、目标、奖励。 |
| `battle_roles.csv` | 战棋兵种基础数值。 |
| `common_units.csv` | 战棋常见单位和资源路径。 |
| `terrain_rules.csv` | 地形防御、移动消耗、颜色。 |
| `ai_profiles.csv` | 敌方 AI 行为风格。 |

## 美术资源提交规则

Unity 资源必须连 `.meta` 一起提交。

例如新增：

```text
Assets/Resources/Art/Portraits/portrait_xxx.png
Assets/Resources/Art/Portraits/portrait_xxx.png.meta
```

两个都要进 Git。

资源目录：

| 目录 | 用途 |
| --- | --- |
| `Assets/Resources/Art/Portraits` | 角色立绘。 |
| `Assets/Resources/Art/Scenes` | 场景原画。 |
| `Assets/Resources/Art/BattleUnits` | 战棋单位序列帧。 |
| `Assets/Resources/Art/Terrain` | 战棋地形图。 |
| `Assets/Resources/Art/UI` | UI 按钮和面板。 |

不要随便改资源文件名。文件名改了以后，配置表或代码里的资源路径也要同步改。

## 打包测试

需要给别人测试时，双击：

```text
一键打包安装包.bat
```

打包结果在：

```text
Builds/Installers
```

注意：`Builds/` 是本地构建产物，不提交 Git。

## 常见问题

### 1. git 不是内部或外部命令

说明 Git 没装好，或者安装后没有重新打开 cmd。

解决：

```text
重新安装 Git for Windows
关闭 cmd
重新打开 cmd
git --version
```

### 2. git lfs 不是命令

说明 Git LFS 没装。

解决：

```text
安装 Git LFS
git lfs install
git lfs pull
```

### 3. 图片变成很小的文本文件

这是 LFS 没拉下来。

解决：

```bat
cd /d D:\paotuan\MingLuUnity
git lfs pull
```

### 4. Unity 打开后很多资源丢失

先确认：

```bat
git lfs pull
```

如果还是不行，关闭 Unity，删除本地 `Library/`，重新打开项目让 Unity 重导入。

### 5. push 时要求登录 GitHub

选择：

```text
Sign in with your browser
```

浏览器登录 GitHub 后授权 `Git Credential Manager`。

不要优先选 Token，除非你知道怎么创建 Personal Access Token。

### 6. push 失败，提示没有权限

让仓库负责人把你加入 collaborator。

路径：

```text
GitHub 仓库 -> Settings -> Collaborators -> Add people
```

### 7. 出现冲突

不要乱点覆盖。先联系负责人或程序。

常见处理方式是：

```bat
git status
```

把冲突文件、你改了什么、报错截图发给负责人。
